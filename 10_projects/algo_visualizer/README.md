# 项目 D · 算法可视化

> 目标：在终端里用 ASCII 动画演示排序算法和二叉搜索树。
>
> ```powershell
> python solution.py sort --algo bubble --size 15
> python solution.py sort --algo quick --size 15 --delay 0.02
> python solution.py sort --algo bubble --no-animate     # 不放动画，直接出结果
> python solution.py bst --values 5,3,8,1,4,7,9
> python solution.py test
> ```

---

## 一、为什么值得做这个

把算法「画出来」会逼你想清楚一件平时可以糊弄过去的事：**每一步到底改了什么。**

写 `bubble_sort` 的时候，你只需要知道「最后结果是排好序的」。
要画出每一帧，你必须明确回答：

- 这一轮比较的是哪两个下标？
- 交换发生在哪一步？
- 已经排好的部分是哪些？（它们不该再参与比较）
- 这一轮结束时，哪些元素的位置已经**确定**了？

**答不上来，说明你其实没完全理解这个算法。**

---

## 二、核心设计：算法用生成器产出「帧」

这是整个项目最漂亮的地方：

```python
@dataclass
class Frame:
    values: list[int]          # 当前数组快照
    highlight: tuple[int, ...] # 需要高亮的下标
    note: str                  # 这一步在干什么

def bubble_sort(data: list[int]) -> Iterator[Frame]:
    ...
    yield Frame(values[:], (j, j + 1), f"比较 {values[j]} 和 {values[j+1]}")
```

**算法只管计算和 `yield` 帧，完全不知道有没有人画它。渲染器只管把帧画出来，
完全不知道这些帧是怎么算出来的。** 两者通过 `Frame` 这个数据结构解耦。

好处立竿见影：

| 好处 | 说明 |
|------|------|
| **可测试** | 断言「最后一帧是排好序的」，不需要跑动画、不需要 sleep |
| **可复用** | 同一批帧，既能画成柱子，也能打印成文本、导出成 JSON |
| **不阻塞** | 生成器是惰性的，你不迭代它就不计算 |
| **能暂停** | `--step` 模式可以一帧一帧手动看 |

这套「**算法产出事件流，渲染器消费事件流**」的模式，
在真实项目里到处都是—— diff 工具、调试器、游戏引擎、编译器的报错定位，
全是这个结构。

---

## 三、要实现的算法

每个算法都是一个生成器，**不许修改传入的列表**（先 `list(data)` 复制一份）。

### `bubble_sort`

每轮把最大的元素「冒」到末尾。产出的帧要能看出：

- 正在比较哪两个（`highlight`）
- 已排好的尾部区域（可以用 `note` 说明）

### `insertion_sort`

维护一个「已排序的前缀」，每次把下一个元素插到正确位置。
帧要能看出插入的过程（元素一个个往左挪）。

### `quick_sort`

递归实现。产出的帧要能看出：

- 选中的基准（pivot）是谁
- 分区（partition）的过程

**提示**：递归生成器要用 `yield from`。

```python
def quick_sort(data, lo, hi):
    ...
    yield from quick_sort(data, lo, pivot - 1)
```

### `bst_insert`（二叉树）

不是排序，是**构建过程**：每次插入一个值，产出一帧当前树的样子。

## 四、二叉搜索树的 ASCII 渲染

这是本项目技术含量最高的一块。

### 先定义节点

```python
@dataclass
class Node:
    value: int
    left: "Node | None" = None
    right: "Node | None" = None
```

### 横向渲染的思路

目标效果：

```
        5
      /   \
     3     8
    / \   /
   1   4 7
```

**关键洞察：中序遍历的顺序，就是节点从左到右的顺序。**

所以：

1. 先中序遍历一遍，给每个节点分配一个「列号」（第几个被访问到的）
2. 每个节点占固定宽度（比如 4 列），列号 × 4 就是它的横坐标
3. 深度 × 2 就是它的纵坐标（中间空一行放连接线）
4. 连接线：父节点在 `row`，子节点在 `row+2`，中间那行 `row+1` 画 `/` 和 `\`

**为什么中序就能定横坐标？** 因为 BST 的中序遍历是升序的，
而画出来的图从左到右也是升序——两者天然一致。

### 简化版：纵向缩进树

如果横向渲染卡住了，可以先做这个版本，它能用且不会错：

```
5
|-- 3
|   |-- 1
|   `-- 4
`-- 8
    `-- 7
```

递归 + 前缀字符串，二十行就能写完。**先做对，再做好看。**

## 五、动画与兼容性

### 关键约束：必须能在 VS Code 的集成终端里正常显示

> 跑这个项目请用 **`Ctrl+F5`**（或在集成终端里 `python solution.py ...`）。
> **别在「调试控制台」里看动画** —— 它是纯文本视图，不渲染 ANSI 转义，
> 动画会糊成一团。本课程的 `.vscode/launch.json` 已经把调试输出指向集成终端，
> 所以按 `F5` 也一样正常。

- **不要用 `curses`** —— 它在 Windows 上的 Python 里根本没有
- **不要用 `os.system("cls")`** —— 每次清屏会闪，而且跨平台行为不一致
- 用 **ANSI 转义序列**：`\x1b[H`（光标回左上角）+ `\x1b[J`（清除到屏幕末尾）

```python
def animate(frames, delay: float, out) -> None:
    for frame in frames:
        out.write("\x1b[H\x1b[J")     # 回家 + 清屏
        out.write(render(frame))
        out.flush()                    # !!! 必须 flush，否则动画会卡在缓冲区里
        time.sleep(delay)
```

### 两块必须防的坑

**① 非交互环境要自动降级。**
如果把输出重定向到文件（`python solution.py sort > out.txt`），
ANSI 转义序列会变成一堆乱码写进文件。所以：

```python
if not sys.stdout.isatty():
    # 不做动画，只输出最终结果
```

或者干脆提供 `--no-animate` 让用户显式关掉。**这个项目两者都做。**

**② `flush()` 不能忘。**
不 flush 的话输出会卡在缓冲区，动画要等程序结束才一次性显示出来——
"动画不动" 十有八九就是这个原因。

### 条形图的宽度

- 终端宽度用 `shutil.get_terminal_size().columns` 拿，取不到就默认 80
- 柱子的最大宽度按数据最大值等比缩放
- **用 `#` 和空格，不要用 `█` 之类的方块字符** —— Windows 控制台默认 GBK，
  这类字符可能显示成乱码（本课程所有模块都遵守这条）

## 六、分阶段提示

### 第 1 步：`Frame` + `bubble_sort`（1 小时）

先只写冒泡。**自测**：把最后一帧的值取出来，断言它是排好序的。

### 第 2 步：`render_sort_frame`（1 小时）

把一帧画成多行文本。先不管动画，`print` 出来看看就行。

### 第 3 步：`animate`（30 分钟）

加 ANSI 清屏和 `flush()`。如果动画不动，第一件事就是检查 `flush`。

### 第 4 步：`insertion_sort` 和 `quick_sort`（1.5 小时）

quick_sort 用 `yield from` 递归。

### 第 5 步：BST（1.5 小时）

`bst_insert` 生成器 + 渲染。渲染先做纵向缩进版，再做横向版。

### 第 6 步：CLI + `--no-animate`（30 分钟）

## 七、验收标准

- [ ] 三种排序的**最后一帧都是排好序的**（自测里会验）
- [ ] 排序过程不修改传入的列表（自测里会验）
- [ ] 每一帧的 `highlight` 下标都在合法范围内
- [ ] `--no-animate` 模式不输出任何 ANSI 转义序列
- [ ] `--algo` 传入未知算法时给出友好提示，退出码非 0
- [ ] BST 的渲染结果里，**从左到右读就是升序**
- [ ] 动画模式下每帧都有 `flush()`
- [ ] 空列表、单元素、已排好序、完全逆序 四种输入都不崩

## 八、做完之后的延伸

1. **加更多算法**：归并排序、堆排序、希尔排序（帧的设计是一样的）
2. **加指标显示**：每帧显示「比较次数 / 交换次数」，能直观看出快排为什么快
3. **加 `--step` 模式**：一帧一帧按回车，比自动播放看得清楚得多
4. **导出成 GIF**：把每帧渲染成图片再拼起来（需要 Pillow）
5. **对比模式**：同一组数据同时跑两种算法，左右并排显示

第 2 条特别推荐——你会亲眼看到冒泡排序的比较次数是 `n²/2` 量级，
而快排是 `n log n`。**这比看复杂度表格直观一百倍。**
