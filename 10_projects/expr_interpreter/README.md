# 项目 A · 表达式解释器

> 目标：实现一个能正确计算下面这些表达式的解释器
>
> ```
> 1 + 2 * 3                    -> 7
> (1 + 2) * 3                  -> 9
> 2 ^ 3 ^ 2                    -> 512      （右结合！）
> -2 ^ 2                       -> -4       （一元负号优先级低于 ^）
> sqrt(16) + abs(-3)           -> 7.0
> x * (y + 1)                  -> 依赖变量
> max(1, 2 * 3, 4)             -> 6
> ```
>
> 并且错误要能定位到**具体的列**：
>
> ```
> >>> 1 + * 2
> 语法错误：第 5 列：'*' 前面缺少操作数
>   1 + * 2
>       ^
> ```

---

## 一、为什么值得做这个

解释器是「分层设计」最经典的例子。整个问题被切成三个阶段，
每个阶段**只依赖前一个阶段的输出**：

```
    "1 + 2 * 3"
         │
         ▼  ① 词法分析（Lexer / Tokenizer）
    [NUM(1)] [OP(+)] [NUM(2)] [OP(*)] [NUM(3)] [EOF]
         │
         ▼  ② 语法分析（Parser）
         BinOp(+)
        /        \
     NUM(1)    BinOp(*)
               /      \
            NUM(2)   NUM(3)
         │
         ▼  ③ 求值（Evaluator）
          7
```

这个结构带来三个巨大的好处：

1. **每层可以单独测试**。词法分析器的测试不需要构造语法树，求值器的测试不需要写字符串。
2. **改一层不影响其他层**。想加个新运算符？只改词法和语法。想加个新函数？只改求值器的环境。
3. **错误能精确定位**。词法层报「这里有个非法字符」，语法层报「这里少了右括号」，
   而不是笼统的「表达式不对」。

**这个「分层 + 每层一个数据结构」的套路，可以套用到几乎所有解析类问题上**——
读配置文件、解析协议、处理 DSL、写模板引擎，全是同一个骨架。

---

## 二、阶段一：词法分析

把字符串切成一个个 **Token**（词法单元）。

### 要处理的 Token 类型

| 类型 | 例子 | 说明 |
|------|------|------|
| `NUMBER` | `3`、`3.14`、`.5`、`1e3` | 浮点数，最后统一转成 `float` |
| `IDENT` | `x`、`sqrt`、`my_var2` | 标识符：字母或下划线开头 |
| `OP` | `+ - * / % ^` | 运算符 |
| `LPAREN` / `RPAREN` | `(` `)` | 括号 |
| `COMMA` | `,` | 逗号（函数参数分隔） |
| `EOF` | — | 结束标记 |

### 关键设计：为什么要有一个 EOF Token

因为**语法分析器永远需要「向前看一个 Token」**。
如果不放 EOF，分析器在读到结尾时必须到处判空，代码会变得很脏。
放一个 `EOF` 当哨兵，分析器就只需要判断「当前 Token 是不是 EOF」。

### 每个 Token 都要记录位置

```python
@dataclass
class Token:
    kind: str      # "NUMBER" / "OP" / ...
    value: str     # 原始文本
    pos: int       # 在输入字符串里的起始下标
```

`pos` 是错误信息能定位到列的唯一依据。**别省这个字段**——
很多手写解析器最后做不了好的错误提示，就是因为一开始没记位置，
事后想加就得把整条链路都改一遍。

### 提示

- 用一个游标 `self.pos` 在字符串上滑动，写一个 `_peek()` 和 `_advance()`
- 数字的识别要小心：`1.` 和 `.5` 都是合法的，但单独一个 `.` 不是
- 遇到不认识的字符，立刻抛异常，别跳过——跳过了错误会跑到很远的地方才暴露

## 三、阶段二：语法分析

把 Token 列表组装成一棵 **AST（抽象语法树）**。

### 递归下降 + 文法

递归下降的核心思想：**一个文法规则对应一个函数**。

```bnf
expr    := term (('+' | '-') term)*
term    := unary (('*' | '/' | '%') unary)*
unary   := ('+' | '-') unary | power
power   := primary ('^' unary)?
primary := NUMBER
         | IDENT
         | IDENT '(' arglist? ')'
         | '(' expr ')'
arglist := expr (',' expr)*
```

### 为什么这么分层？—— 运算符优先级

**优先级就体现在「谁调用谁」上。**
`expr` 调 `term`，`term` 调 `unary`，越靠下的规则结合得越紧：

```
优先级 低 ─────────────────────────────────► 高
        + -        * / %        ^        一元负号
       expr   →    term    →   power  →   unary
```

**结合性则体现在循环的写法上**：

```python
def expr(self):
    node = self.term()
    while self._match("+", "-"):        # 左结合：循环累积
        op = ...
        right = self.term()
        node = BinOp(op, node, right)   # 把已算出的结果当左子树
    return node
```

左结合 `1 - 2 - 3` 会解析成 `(1 - 2) - 3`，因为每轮循环都把**之前的结果**
当作左子树。

而 `^` 是**右结合**的（`2^3^2 = 2^(3^2) = 512`），所以要用递归：

```python
def power(self):
    base = self.primary()
    if self._match("^"):
        exponent = self.unary()          # 递归，不是循环！
        return BinOp("^", base, exponent)
    return base
```

**这是整个项目最需要想清楚的地方。** 建议动手前先在纸上推导一遍
`2 ^ 3 ^ 2` 和 `-2 ^ 2` 的解析过程。

### 关于 `-2 ^ 2 = -4`

这不是 bug，是约定俗成的规则：**一元负号的优先级比 `^` 低**。
把 `unary` 放在 `power` 下面（而不是上面）就自然得到这个结果：
`power` 先算出 `2^2=4`，`unary` 再取负。

（如果你觉得反直觉：数学上 `-2²` 确实读作 `-(2²)`。C、Python、Excel 都这么算。）

## 四、阶段三：求值

在 AST 上递归下降，带一个**环境**（变量表）。

```python
class Evaluator:
    def __init__(self, env=None, functions=None):
        self.env = dict(env or {})          # 变量：{"x": 3.0}
        self.functions = functions or ...   # 函数：{"sqrt": math.sqrt}
```

### 内置函数

至少支持：`sqrt` `abs` `min` `max` `pow` `floor` `ceil` `round` `sin` `cos` `log` `log10` `exp`

直接用 `math` 模块里的同名函数就行——**别自己实现平方根**。

### 三个要处理的错误

| 情况 | 异常 |
|------|------|
| `1 / 0` | `ZeroDivisionError` → 包装成 `EvaluationError("除以零")` |
| 用了没定义的变量 `y` | `EvaluationError("未定义的变量：y")` |
| 调用不存在的函数 `foo(1)` | `EvaluationError("未定义的函数：foo")` |

### `min` / `max` 要特殊处理

它们接受**任意个参数**，所以 AST 节点 `Call` 的参数是列表，直接 `*args` 传进去。

## 五、分阶段提示

**不要试图一次写完。** 按这个顺序，每一步都能独立验证：

### 第 1 步：只支持单个数字（1 小时）

```
Lexer.tokenize("42")  ->  [Token(NUMBER, "42", 0), Token(EOF, "", 2)]
Parser.parse(...)     ->  Number(42.0)
Evaluator.eval(...)   ->  42.0
```

跑通这条最细的链路，你就理解了三个阶段的接口。

### 第 2 步：支持 `+ - * /` 和括号（1~2 小时）

实现完整的 `expr / term / unary / primary` 四层文法。
**先写 `primary`，再往上搭**——它是递归的出口。

测这几个：`1+2*3`、`(1+2)*3`、`1-2-3`（必须得 `-4`）。

### 第 3 步：加 `^`、`%` 和一元负号（1 小时）

重点验证 `2^3^2 == 512` 和 `-2^2 == -4`。这两个过不了就是文法写错了。

### 第 4 步：加变量和函数调用（1 小时）

`sqrt(16)`、`max(1, 2*3, 4)`、`x * (y + 1)`。

### 第 5 步：把错误信息做漂亮（1 小时）

给异常带上 `pos`，渲染出带 `^` 指示的报错。

```
语法错误：第 5 列：'*' 前面缺少操作数
  1 + * 2
      ^
```

这是**投入产出比最高的一步**。同样的功能，报错清晰的那个才好用。

### 第 6 步：交互式 REPL（可选，30 分钟）

用 `input()` 循环读表达式，支持 `x = 5` 赋值和 `:vars` 查看变量。
会让你有「这东西真能用了」的感觉。

## 七、做完之后的延伸

1. **加比较运算符**：`<` `>` `==`，以及三目 `a if cond else b`
2. **加字符串字面量**：`"hello" + " world"`
3. **加赋值语句**：`x = 1 + 2`（提示：这需要把「表达式求值」升级成「语句执行」）
4. **加常量折叠优化**：解析完遍历一遍 AST，把 `2 * 3` 直接换成 `6`
5. **加变量依赖分析**：给定 AST，返回它用到了哪些变量（提示：递归 + 集合）

第 4 条会让你第一次接触「编译期优化」这个概念——
它是一个纯粹的 AST 变换，和求值器完全解耦。这就是分层设计的回报。
