# 模块 10 · 综合项目

> 前九个模块是「学」，这一个是「做」。
>
> 这四个项目没有新知识点，但每一个都会逼你把学过的东西**串起来用**。
> 它们是刻意选出来的：分别对应「解析」「数据处理」「并发」「算法可视化」四类
> 最常见的真实需求，而且都能在几百行内做完。

---

## 怎么用这个模块

每个项目目录下有三个文件：

| 文件 | 作用 |
|------|------|
| `README.md` | 需求、分阶段提示、验收标准 |
| `starter.py` | 骨架 + `TODO`。先读它，再动手 |
| `solution.py` | 参考实现，可以直接运行看效果 |

**不要一上来就看 `solution.py`。** 正确顺序是：

```
1. 读 README 的「需求」和「分阶段提示」
2. 打开 starter.py，它会告诉你每个函数该做什么
3. 自己写，卡住了再回头看 README 的对应章节
4. 全部做完，跑通 starter.py 里的自测
5. 最后才对照 solution.py —— 重点看「为什么这么组织代码」，不是看语法
```

## 四个项目

### A · `expr_interpreter` —— 表达式解释器

从零实现一个能算 `(1 + 2) * 3 ^ 2 - sqrt(16)` 的解释器。

**练到**：模块 02（数据结构）、03（函数与闭包）、04（类与魔术方法）、06（自定义异常）。

**为什么选它**：写解释器是「把大问题拆成小问题」的极致训练。
词法分析、语法分析、求值三个阶段各自独立、各自可测。
而且你会第一次真切体会到**递归下降为什么需要文法设计**——
`1 - 2 - 3` 到底是 `(1-2)-3` 还是 `1-(2-3)`，这个问题的答案写在文法里。

**难度**：★★★★☆

### B · `log_analyzer` —— 日志分析 CLI

读一个访问日志，输出 Top IP、状态码分布、最慢的请求、错误率。

**练到**：模块 02（Counter/defaultdict）、06（文件与异常）、07（argparse/re/datetime）。

**为什么选它**：这是数据类工作的标准形态——**解析 → 聚合 → 呈现**。
真实工作中你会反复写这种三段式，只是数据源从日志换成 CSV、数据库、API。
重点在「脏数据处理」：真实日志里永远有对不上的行，你的程序必须活下来。

**难度**：★★★☆☆

### C · `async_crawler` —— 并发抓取器

用 asyncio 并发抓取一批 URL，带限流、超时、重试、结果落盘。

**练到**：模块 06、08（asyncio / Semaphore / TaskGroup）。

**为什么选它**：并发是「知道概念」和「写得对」差距最大的一块。
限流、超时、重试、部分失败——这四个词每个都对应一段容易写错的代码。
项目内置**离线模式**，没网也能完整跑通并被测试。

**难度**：★★★★☆

### D · `algo_visualizer` —— 算法可视化

在终端里用 ASCII 动画演示冒泡排序、快速排序、二叉搜索树的插入。

**练到**：模块 02、04、05（生成器用作动画帧）。

**为什么选它**：把算法「画出来」会强迫你想清楚每一步到底改了什么。
而且**用生成器产出动画帧**是个非常漂亮的模式——
算法只管计算，渲染只管画，两者通过 `yield` 解耦，各测各的。

**难度**：★★★☆☆

## 建议的节奏

| 项目 | 建议时间 | 做完的标志 |
|------|---------|-----------|
| A 解释器 | 4~6 小时 | 能算复杂表达式，错误能定位到列 |
| B 日志分析 | 2~3 小时 | 能处理含脏行的真实日志 |
| C 并发抓取 | 3~5 小时 | 离线模式跑通，限流和重试都可观测 |
| D 可视化 | 2~4 小时 | 动画流畅，`--no-animate` 模式也能出结果 |

**做完之后做一件事**：给每个项目写几条 pytest 测试（模块 09 学的）。
你会发现「为别人写的代码写测试」和「为自己写的代码写测试」是两种体验。

## 验收标准（通用）

一个项目算「做完了」，必须满足：

- [ ] 能直接运行，不需要改代码（`python solution.py` 或 `python starter.py`）
- [ ] 有 `if __name__ == "__main__":` 保护
- [ ] 错误输入给出**人类能看懂**的提示，而不是 traceback
- [ ] 所有函数都有类型注解
- [ ] 至少有 3 条自测断言，覆盖正常路径和错误路径
- [ ] 没有 `except: pass`，没有裸 `except`
- [ ] 代码能被 `ruff check` 通过
